An article filed in a category is served at `/blog/<category>/<slug>` (`/en/blog/<category>/<slug>` in English) when its route says so, and every other address of it answers a 301 to that one: the old `/blog/<slug>`, a wrong category, a renamed or moved category — query string kept, never a second 200. An entry with no category stays at `/blog/<slug>`. The canonical link, the hreflang pair, the sitemap, the feeds, `llms.txt`, the term archives, search results, widgets, menus, the language switcher, the admin permalink preview, the MCP and agent tools and the webhook events all name the same canonical address. New command for a site that already exists (the schema being read-only in production, ADR-0010): `cogenta schema set-route <collection> "<pattern>" [--write]` changes one collection's pattern in `cogenta.schema.mjs` — a dry run by default that lists how many published entries change address, the original kept as `cogenta.schema.mjs.before-set-route`, nothing else touched. For example `cogenta schema set-route post "/blog/:category/:slug" --write`. When the new pattern only adds the category, old addresses answer a 301 by themselves; for any other change the command lists the `301` redirects to add in the admin.
