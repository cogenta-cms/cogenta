Méthode — rappel du plan de test

Trois lots indépendants, chacun testé comme un parcours utilisateur réel : configurer, observer le résultat sur l'écran et sur le site public, noter l'écart avec ce qu'un CMS comparable (WordPress, Drupal, Strapi) ferait.

Lot A — Contenu & apparence

Tableau de bord, création/édition/publication de contenu, slug, médias, taxonomies, builder visuel, historique, thèmes, menus.

Lot B — Utilisateurs, sécurité & outils

Connexion, utilisateurs & rôles, clés API, santé, mises à jour, audit, réglages, export/import/sauvegarde/RGPD.

Lot C — Site public & transverse

Pages publiques, recherche, formulaires, commentaires, SEO, redirections, statistiques, écrans IA en l'absence de fournisseur.

Défauts corrigés cette session

Chacun vérifié en direct dans le navigateur après correction, puis par les suites de tests concernées.

Aucune génération automatique du slug depuis le titre

MajeurCorrigé
Constat
Lot A — taper un titre laissait le champ « slug » vide, contrairement à WordPress/Drupal/Strapi. C'est ce qui avait produit l'article de production sans URL qui faisait planter la page d'accueil (session précédente).
Racine
deriveSlug() existe et est testée côté serveur, mais n'est appelée par aucun chemin d'écriture ; côté admin, le champ slug documentait lui-même l'absence de dérivation.
Fichier
packages/admin/src/routes/entry-edit.tsx
Correction — le slug se dérive maintenant du titre à chaque frappe, tant qu'il reste égal à la dernière valeur proposée automatiquement ; un slug déjà présent au chargement (article existant) n'est jamais réécrit. Vérifié en direct + 21/21 tests entry-edit.test.tsx.

Une boîte de dialogue de création ne se ferme jamais après succès

MajeurCorrigé — transversal
Constat
Lot B — sur Utilisateurs et Clés API, après une création réussie, ✕ / Annuler / Échap ne ferment plus la modale. Reproduit en isolation, hors de tout doute lié à l'environnement de test partagé.
Racine
Le composant de modale nomme quatre animations CSS de fermeture sur les attributs Radix — aucune des quatre @keyframes correspondantes n'était définie nulle part. Sans animationend, Radix attendait indéfiniment avant de démonter la boîte, qui restait affichée et interactive.
Fichier
packages/admin/src/styles/base.css
Correction — les quatre @keyframes manquantes ajoutées. Un seul composant partagé par toutes les modales de l'admin (menus, taxonomies, corbeille compris) — un seul correctif les couvre toutes. Vérifié en direct (reproduction puis re-test) + 34/34 tests users/api-keys.

Une route admin inconnue affiche une page totalement blanche

MajeurCorrigé
Constat
Lot B — /admin/updates, /admin/export ou toute URL inventée sous /admin/* rendaient une page vide : sans menu, sans en-tête, sans message.
Racine
Aucune route « catch-all » : react-router ne rend rien du tout — y compris le layout parent — quand aucune route ne correspond.
Fichier
packages/admin/src/app.tsx, nouveau routes/not-found.tsx
Correction — route path="*" ajoutée en dernier enfant du groupe authentifié. Le menu et l'en-tête restent visibles, un message explique la situation. Vérifié en direct.

Message d'erreur de connexion non traduit

MineurCorrigé
Constat
Lot B — mauvais mot de passe → « Incorrect email or password. » en anglais, au milieu d'un écran entièrement français.
Racine
Le message brut du serveur (un contrat d'API stable, jamais localisé) était affiché tel quel pour toute erreur, sans jamais passer par la traduction.
Fichier
packages/admin/src/routes/login.tsx
Correction — les codes d'erreur qu'un essai de connexion produit réellement sont traduits vers la bonne clé du contexte appelant — mot de passe, code TOTP et code de récupération n'ont pas le même sens pour un même code d'erreur réutilisé par le serveur. 14/14 tests login.test.tsx.

Majeur → reclasséTexte corrigé

Message « Statut changé en Publié » resté affiché après duplication

MineurCorrigé
Constat
Lot A — dupliquer un article publié : la copie (en réalité Brouillon) affiche quand même « Statut changé en Publié. ».
Racine
La navigation vers la copie ne change que le paramètre :id — react-router réutilise la même instance du composant plutôt que de la remonter, donc le message de l'action précédente ne se réinitialise jamais tout seul.
Fichier
packages/admin/src/routes/entry-edit.tsx
Correction — le message est explicitement effacé avant la navigation vers la copie.

Reclassés « pas un défaut » après vérification

Trois constats décrivaient un symptôme réel mais une cause différente de celle supposée — le code a été relu avant toute correction.

« Écran de mise à jour introuvable »

Pas un défaut

L'écran existe bel et bien, à /admin/ops-settings — chargé automatiquement à l'ouverture, pas un onglet caché. Le nav le liste sous « Sécurité & webhooks », un libellé qui ne laisse pas deviner qu'il contient aussi les mises à jour. Suggestion de renommage notée dans le plan de correction, non appliquée — hors périmètre de cette passe.

« Export / Sauvegarde / RGPD introuvable »

Pas un défaut

Confirmé par le commit de fusion lui-même : ces fonctions sont délibérément CLI-only (cogenta export/import/backup/restore), jamais exposées par l'API admin. Rien à corriger ici au-delà du texte du widget ci-dessus.

« Écran Taxonomies absent de la navigation »

Pas un défaut

Le lien existe (shell/nav-items.ts) mais ne s'affiche que si le site a réellement déclaré au moins une taxonomie — ce qui n'est pas le cas de local-playground. Comportement voulu : pas de lien mort vers un écran qui n'aurait rien à montrer.
